# 时证：应用与评估架构

![系统架构](../assets/architecture/chronofin_architecture.png)

本图概括当前实现，分为应用流程和评估验证两部分。全部模型生成、修订与语义评判使用腾讯 TokenHub 的 Hy3；没有训练或微调。

| 图中模块 | 实际实现与边界 |
| --- | --- |
| 研究任务与资料 | `research_app.py` 接收问题、信息截止日、文字 PDF 或资料卡。文字 PDF 按页切分；扫描 OCR 不在当前实现范围。 |
| 时点与原文证据 | `pdf_research.py` 的 `document` / `retrieve` 登记身份、日期、页码并先过滤未来正文；`pdf_research_v5.py` 调用 Hy3 选择原文，`span_evidence.py` 回绑原文行并检查数值。已登记资料卡可直接进入生成流程。 |
| 生成与反证修订 | 资料卡路径为 `brief.generate`；原生 PDF 路径为 `native_generation_v5.generate`。本地 `financial_operations.compile_requests` 编译受支持计算，Hy3 根据原文、计算结果与绑定问题修订；必要时进行一次有界的证据修复。图中展示逻辑阶段，不承诺固定调用次数。 |
| 可复核研究简报 | `research_app.py`、`web/index.html` 展示研究结论、证据账本、核查提示、分维诊断与 JSON 导出；支持实时调用和真实结果回放。 |
| 评测样本与参考要点 | `data/brief/`、`data/native/` 及实验脚本提供原文、问题、参考要点、难例、反例和变形样本。`brief.public_case` 不向生成器传递参考清单，生成和修订也不接收人工标签。 |
| 十维评估 | `brief.evaluate` 执行规则与诊断分聚合；`grounded.judge` 和 `pdf_research_v5.judge` 执行 Hy3 语义判定及证据绑定。原生 PDF 路径分别绑定来源原文与候选原句，片段存在不等于语义判断必然正确。 |
| 无独立参考清单 | `live_audit.partial_scorecard` 将重要信息覆盖、反证完整性和未知边界三维标为未测，总分为 `null`，保留可测的分维诊断。 |
| 评估方法验证 | `scripts/` 与 `results/` 保存判别力、重复及顺序一致性、攻击与等价变形、同调用次数对照、公开人工标签验证等实验。公开人工标签实验检验三分类一致性，不能代替十维专家盲标。 |

连线表示数据或诊断的传递：候选答卷进入评估；诊断结果返回工作台；评估记录用于方法有效性分析。参考清单只进入评判环节，图中没有将其连回生成器。

十维名称在图中作了简写，完整定义、权重和可操作判据以[开放式评估方法](开放式评估方法.md)为准。图中不包含未经实现的多 Agent、向量数据库、训练服务或自动专家标注。

图像文件位于 `assets/architecture/`：PNG 用于 README 的稳定显示，SVG 保留可编辑文字并嵌入所需字体，PDF 可用于报告。字体来自本仓库附带许可的 Noto Sans CJK。`build.py` 保存布局源代码，`verify.py` 以浏览器实际文字边界检查溢出、重叠与连线碰撞，检查结果见 `layout_verification.json`。
