# ChronoFin「时证」v2 卓越候选严格自审

> 自审日期：2026-08-27  
> 评审口径：以当前源码、落盘结果、测试与交付物为证据；不是官方评审结论  
> 历史快照：v0 为 71/100，v1 为 82/100；二者仅用于记录项目演进  
> 当前裁决：**v2 内部评分 87/100，达到“卓越候选”阈值，但尚未达到“可保证获奖”或“已完成提交”的含义。**

任务依据见[犀牛鸟任务 PDF](../../tasks/%E7%8A%80%E7%89%9B%E9%B8%9F%E5%BC%80%E6%BA%90-%E5%AE%9E%E6%88%98%E4%BB%BB%E5%8A%A1-%E6%B7%B7%E5%85%83%E5%A4%A7%E8%AF%AD%E8%A8%80%E6%A8%A1%E5%9E%8B%E9%A1%B9%E7%9B%AE.pdf)，项目定位与相邻工作见[研究版图](research_landscape.md)，所有数值必须回到链接的 JSON 核验。

## 1. 一句话结论

ChronoFin 已不只是“带引用的财报 RAG”。它把三个可以被证伪的机制连成闭环：

> **point-in-time 可知性边界 → typed proof graph 可执行承诺 → causal metamorphic evaluation 反事实审计**

v2 达到内部卓越候选线的理由，不是界面更漂亮或 Agent 更多，而是模型的自由文本被压缩到确定性信任边界内：时间、来源身份、原文 span、实体、财期、指标槽位、单位、算术、依赖图、摘要与拒答都能被独立复算；36 类已形式化破坏均会降分，2 类等价变形不误伤；四策略消融显示完整系统提供了内部组件基线无法覆盖的增量。

但本结论有明确上限：**没有人工专家盲标、没有真正 held-out、没有独立外部强基线。** 当前真实端到端主案例仍集中在腾讯一条披露链；Apple、Microsoft、NVIDIA 挑战是 AI 策展的确定性 conformance 检查。内部 87 分只能表示“有资格作为卓越候选提交”，绝不等于官方评委一定评为卓越，更不等于奖金或证书已获得。

## 2. 内部 rubric、阈值与否决门槛

### 2.1 加权 rubric

| 维度 | 权重 | 卓越候选锚点 |
| --- | ---: | --- |
| 问题与创新 | 20 | 不是通用聊天框；贡献可被明确消融、攻击和失败案例证伪，并诚实界定 prior art |
| 任务契合与 Hy3 必要性 | 15 | 有可运行 Hy3 应用；说明语义模型与确定性层各自不可替代的职责；应用与自定义评测闭环 |
| 技术深度与信任边界 | 20 | 时间隔离、来源回绑、安全计算、类型化证明图、故障门禁和拒答边界均落到代码 |
| 评估可靠性 | 25 | 多类困难/负面/等价样本、good/medium/bad、消融、重复一致性、冻结挑战、失败归因与可复算结果 |
| Demo 冲击力 | 10 | 两分钟内让评委直接看到“截止日前拒答、日后解锁、证据/公式、受控攻击触发门禁” |
| 可复现性与提交质量 | 10 | README、环境、许可、测试、结果、无密钥、数据来源/哈希、cleanroom、公开 Git 和演示资产齐全 |

内部“卓越候选”必须同时满足：

1. 总分不低于 **85/100**；
2. 技术深度不低于 **18/20**，评估可靠性不低于 **19/25**；
3. 任一维度不得低于该维满分的七成；
4. 下列正确性否决项全部通过；
5. 最终提交前，交付否决项全部关闭。

由于当前没有人工效度、真正 held-out 和外部强基线，本 rubric 对总分设置 **89 分证据上限**。这避免把大规模内部自洽误写成外部可靠性。

### 2.2 正确性否决项

以下任一项成立，直接取消“卓越候选”，不允许靠其他维度平均回来：

- 截止日后的来源能进入提示或作为结论依据，或错误 `known_at` 可以绕过门禁；
- 伪造 quote、document/page/date/URL 身份或不精确引文仍可获得优秀档；
- 实体、财期、指标槽位、单位、公式结果、typed value 与可见文本之间的材料性冲突未被封顶；
- 空答、肯定式 UNKNOWN、无依据一律拒答或利用无关负面证据拒答可以通过；
- 摘要、caveat 等旁路能加入未经 claim ledger 审计的数字、断言、提示注入或投资指令；
- 证明图悬空、成环或派生结论无可追溯操作数仍能通过；
- 结果 JSON 无法由当前源码重跑，或冻结数据/评估器账本哈希不一致；
- 公开提交或 Git 跟踪中含有效密钥、受版权限制的缓存 PDF，或存在未披露的数据来源。

### 2.3 提交否决项

这些不改变项目本体的 87 分，但若在提交时仍缺失，则状态只能是“本地候选”，不能称“提交就绪”：

- 最终源码、文档和结果冻结后，fresh cleanroom 未完整通过；
- 没有可公开访问的 Git 仓库、固定 commit/tag 与 clean-clone 复现记录；
- 没有不超过两分钟、无密钥且可播放的正式演示视频或官方接受的等效资产；
- README、环境、许可证、数据边界、运行命令、结果表和失败案例未与最终版本同步。

## 4. 核心创新：六账本独立重算，而非相信模型自报

Hy3 的 JSON 是候选分析，不是事实证书。v2 将输出拆成六个相互校验的账本；每个账本都由受信任输入重新计算，任何一个失败都可以触发硬门禁。

| 账本 | 独立重算内容 | 模型不能自行决定什么 |
| --- | --- | --- |
| 查询—可回答性账本 | 查询实体、请求财期、指标槽位、answerability 与 claim 类型/覆盖关系 | 不能靠改写问题、空答或无关拒答让结构看似完整 |
| 时间账本 | registry 的 `published_at`、claim `known_at`、查询截止日与未来隔离清单 | 不能自报发布日期，也不能用后来发布的材料回答历史问题 |
| 来源账本 | chunk 身份、document/page/date/URL 回绑以及 quote 是否为精确连续 span | 不能生成一个看似可信的页码或把“有链接”冒充“有证据” |
| 数值账本 | 安全执行公式、操作数来源、单位、执行值、typed value 与 claim 可见文本 | 不能让结构化字段写对、自然语言写错，或借标识符/财年数字蒙混过关 |
| 证明图账本 | Source–Calculation–Claim 节点、边、DAG、叶绑定、后代与非后代 | 不能只在答案末尾事后贴引用；派生值必须承诺其依赖 |
| 表达与政策账本 | 摘要只能投影已审 claim，UNKNOWN 与 caveat 使用确定性模板，检查注入与投资指令 | 不能从摘要、免责声明或拒答尾句重新注入未经审计的断言 |

这六个账本与十维评分不是重复包装：账本给出可验证对象，十维评分汇总诊断，hard gates 负责否决。其产品价值也很直接：研究员不仅看到答案，还能追问“当时是否可知、来源是否同一份报告、数字怎么算、改一处会影响哪里”。

## 5. 当前证据链

### 5.1 36 类攻击、2,736 次压力运行

[synthetic_benchmark.json](../results/synthetic_benchmark.json)固定覆盖 8 个虚构实体、3 个财年、3 个问题族，共 72 个 base tasks。每题运行 36 类 destructive mutation 和 2 类 label-preserving mutation：

- 破坏性运行：72 × 36 = **2,592**；
- 等价变形运行：72 × 2 = **144**；
- 合计：**2,736**；
- 完整系统 PDA = 1.0、IVR = 0.0；
- 36 个 destructive subtype 的 typed-signal recall 均为 1.0；
- 严重度—降分 Spearman = **0.423556**。

最后一项只有中等正相关，且严重度标签未经金融专家标定，因此不能包装成“分值完全校准”。PDA=1、IVR=0 也只证明对预定义形式化攻击的响应，不证明自然世界错误分布中的准确率。

### 5.2 10,944 次四策略消融

[evaluator_ablation.json](../results/evaluator_ablation.json)在同一 2,736-run 矩阵上比较四种内部策略，共 **10,944** 个 strategy-mutation outcomes：

| 策略 | destructive detection rate | IVR |
| --- | ---: | ---: |
| 无审计 plain output | 0.000000 | 0.0 |
| 仅精确引文 | 0.055556 | 0.0 |
| 时点 + 精确引文 | 0.138889 | 0.0 |
| 完整 ChronoFin | 1.000000 | 0.0 |

这支持“时间层、引用层与完整账本/门禁各有增量”的内部机制主张。它**不是外部强基线实验**：前三个策略由本项目组件构造，plain arm 是负对照，不是另一个成熟金融系统；不能据此声称超过 FinanceBench、FinQA、FinRobot 或某个商业产品。

### 5.3 good / medium / bad 与自动化测试

[offline_experiment.json](../results/offline_experiment.json)的当前质量梯度为 **100 / 55 / 40**：完整样本通过；材料性数值/实体类错误被 55 分门禁截断；未来/伪引文类错误被 40 分门禁截断。这里验证的是分层和否决行为，不是三个样本代表总体分布。

当前 `tests/` 已有**至少 116 项**自动化测试，覆盖模型 schema、检索时点、引用回绑、数值血缘、证明图、攻击类型、消融、挑战账本、安全、提交 verifier 与 cleanroom 校验。测试数量不是质量本身；最终结论必须以冻结后的完整套件实际通过为准，不能只数 `test_` 函数。

### 5.4 当前腾讯案例：100/100 与确定性五次一致

当前 v2 的腾讯 FY2025 同一问题使用两个截止日：

- [披露前答案](../results/public_tencent_before_publication_final.json)及其[评分](../results/public_tencent_before_publication_final_score.json)：截至 2025-12-31，系统拒绝猜全年数据，并隔离 2026-04-09 才发布的年报，得分 100；
- [披露后答案](../results/public_tencent_after_publication_final.json)及其[评分](../results/public_tencent_after_publication_final_score.json)：截至 2026-04-10，收入、IFRS/非 IFRS 归母利润和派生利润率均绑定精确表格上下文与计算血缘，得分 100；
- [当前确定性稳定性](../results/public_tencent_current_deterministic_stability.json)：前、后两个答案**各自复算 5 次**，每组分数均为 100，scorecard 哈希完全一致，population std = 0。

这里必须严格区分两类稳定性证据：当前五次运行没有网络、没有模型调用，只证明 v2 确定性评估器对同一输入字节可重复；[历史 Hy3 语义复评](../results/public_tencent_semantic_stability_final.json)曾得到 15/15 supported 和三次 100，但该文件绑定的是历史答案/评估版本，**不能绑定或替代当前 v2 答案的语义判定**。因此本自审不声称当前答案已经获得五次 Hy3 或独立专家语义认可。

### 5.5 双版本挑战：失败保留，但不是 held-out

挑战覆盖 Apple、Microsoft、NVIDIA 的官方短摘录、前后发布日期和 future-leak 负例。必须同时报告两段历史：

1. **历史冻结 v1**：首次运行 base 为 **3/6**，修复独立 materialization adapter 后为 **6/6**；3 个 future-leak 负例均被压到 20。冻结问题、日期、值、quote 和来源哈希没有修改。证据见[首次结果](../results/postfreeze_challenge_v1.json)、[修复后结果](../results/postfreeze_challenge_v1_after_adapter_fix.json)和[报告](postfreeze_challenge_report.md)。
2. **当前评估器回归**：由于随后红队加固改变了 evaluator，历史 evaluator ledger 不能伪装成“当前代码未变”。用同一份已经可见的数据做 current regression，首次为 **0/6**，修复槽位/规范投影适配后为 **6/6**；future-leak 负例仍为 3/3。证据见[首次当前回归](../results/postfreeze_challenge_v1_current_regression.json)和[槽位修复后回归](../results/postfreeze_challenge_v1_current_regression_after_slot_fix.json)。

第二段必须叫**已见回归（seen regression）**，不能叫 post-freeze held-out：这份数据在 v2 hardening 期间已经被查看和用于修复。它的价值是防止版本升级破坏既有行为，不是估计未知数据泛化能力。

### 5.6 cleanroom 的机器裁决

[cleanroom_verification.json](../results/cleanroom_verification.json)是唯一有效的当前状态载体，本文不手写 `pass`。cleanroom 在临时 checkout、新 venv、无 API Key、无网络和无缓存 PDF 下依次执行本地安装、编译、完整测试、结果再生、脱敏、CLI 与 Git 暂存；其中 prerequisite verifier 明确跳过正在构造的 cleanroom 自检，最终再由普通 submission verifier 从外部检查完整报告，避免循环自证。

门槛只有在报告的 `all_passed=true`、source/reproduced SHA-256 同时等于当前树、严格命令协议全部零退出、且随后普通 verifier 通过时才关闭。正确顺序是完成全部代码/结果/文档/GIF → 冻结当前树 → 重跑 cleanroom → 普通 verifier。任何后续材料性编辑都会改变树指纹并自动使旧证明失效。该证明仍只覆盖当前主机/工具链，不是第三方机器复现或密码学签名。

## 6. 可以证明与不能证明

### 可以证明

- 系统在检索/提示前执行 `published_at <= as_of_date`，能在合成与腾讯时间线隔离未来材料；
- 模型自报的来源元数据不受信，citation 会与 registry 独立回绑，quote 必须为精确 span；
- 派生数字可以从 claim 文本追到 typed value、执行结果、公式操作数和来源叶；
- 在 72 个形式化任务上，36 类预定义破坏全部被分型检出，2 类预定义等价变化没有误降分；
- 四策略内部消融显示精确引用、时点控制和完整审计的增量；
- 腾讯披露前/后案例在当前确定性评估器上各自五次复算完全一致；
- 失败版本被保留，历史 v1 与当前 v2 的 evaluator ledger 没有被混为同一个冻结版本。

### 不能证明

- 不能把 72 个模板任务称为 held-out，也不能把 2,736 次 mutation 称为同等数量的独立真实金融问题；
- 不能把当前挑战称为对 v2 的盲测；它是 AI 策展且在 hardening 中已见；
- 不能声称与金融专家一致、达到 human-level，或得到人工审计认可；[人工标注协议](human_annotation_protocol.md)尚未执行；
- 不能声称超过外部强基线；现有四策略是组件消融与负对照；
- 不能把腾讯一个问题族外推为跨公司、跨市场、跨表格格式总体准确率；
- 不能把当前五次确定性复算说成五次 Hy3 语义判断；历史 Hy3 复评不绑定当前字节；
- 不能把 causal fidelity 解释为企业经营因果推断；它只检查证明图对受控证据变化的响应；
- 不能声称公网可复现或正式视频已交付，直到公开仓库、固定 commit 和最终资产真实存在。

## 7. 为何此时可称“卓越候选”，仍不能保证卓越

评委真正可能记住的不是“又做了一个金融 Agent”，而是一个反直觉但重要的演示：**同一份本地语料库、同一个问题，只因截止日不同，系统必须先拒答、后解锁；且每个答案都能经六账本复算。** 再把一个看似细小的来源日期、quote、单位或 claim 文本改错，漂亮的平均分不能掩盖致命问题。

这已经满足本 rubric 对创新、技术深度、内部验证和演示叙事的候选要求。尤其 36 类攻击不是单纯扩数量，而是针对红队发现的真实旁路逐项封堵，并用 10,944 次成对消融验证组件贡献。

仍不能保证官方卓越有三个根本原因：

1. 官方评委的权重、竞争作品和名额未知，内部 rubric 不是官方评分表；
2. 当前证据擅长证明“形式化错误能否被抓住”，不等于证明开放金融问答的总体正确性；
3. 人工效度、真正 held-out、外部强基线和第三方复现仍为空白，这些缺口不能靠更多内部 100 分抵消。

因此最准确标签是：**Conditional Excellent Candidate / 有条件的卓越候选**。

## 10. 评委可能追问的诚实答法

**这不就是 RAG 加规则吗？**  
RAG 负责找文本；ChronoFin 把时间可见性、来源身份、计算血缘和依赖响应变成可执行承诺，并用攻击/等价变形成对检验评估器。内部消融表明仅精确引文或仅加时点仍覆盖不了多数破坏类型。

**为什么一定要 Hy3？规则层不是已经能做完吗？**  
规则层可以审计已经结构化的候选答案，却难以穷举开放问题拆解、跨段落语义归一、口径识别和类型化草案生成；Hy3 负责这些开放语义工作。反过来，Hy3 不能可靠自证发布日期、来源身份和算术，所以两者职责互补。

**100 分是不是代表答案真实正确？**  
不是。100 只表示在该输入、registry、gold/oracle 和当前检查器下没有检出错误。腾讯案例范围窄；形式化 benchmark 是 synthetic；当前没有人工专家总体准确率。

**三公司挑战是 held-out 吗？**  
对历史 v1，它保留了首次 3/6 到修复后 6/6 的冻结失败链；对当前 v2，数据已经在 hardening 中被看到，所以只能称 seen regression，不称 held-out。

**当前稳定性是模型重复吗？**  
不是。当前前/后答案各五次是确定性 evaluator 重算。三次 Hy3 语义复评属于历史 artifact，不绑定当前 v2 输出。

## 11. 最终推荐

**推荐继续以 ChronoFin「时证」作为任务 1 的主提交方向。v2 内部评分 87/100，达到“卓越候选”阈值。**

这个结论建立在当前可审计证据上：六账本独立重算、36 类攻击与 2 类等价变形、2,736 次压力运行、10,944 次组件消融、当前腾讯前后 100/100 且各五次确定性一致、历史挑战 3/6→6/6、当前已见回归 0/6→6/6，以及至少 116 项自动化测试。

同时，**官方评为卓越、获得奖金或证书均无法保证**。最终 cleanroom、公网 Git、固定 commit/release 和正式视频仍是提交前必须由参赛者完成并外部核验的动作；没有人工、真正 held-out 和外部强基线的限制必须继续写在 README、视频和答辩中。只有在 P0 全部关闭后，项目才可从“有条件的卓越候选”升级为“提交就绪的卓越候选”。
