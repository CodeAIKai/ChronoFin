# 开放式金融简报评估方法

实现：`src/chronofin/brief.py`。当前在线研究协议为 `counterbrief-1.2`；代码和数据字节绑定在实验目录的 `protocol.json`。以下阈值是本项目预先设定的研究规则，不是腾讯官方评分标准。

## 为什么不能只比较标准答案

用户需要的是晨会可用的研究结论：哪些业务驱动得到支持、什么事实削弱结论、还不能知道什么、接下来应该查什么。文字组织、观点强弱、列举次序没有唯一标准答案。参考清单只列核心信息和不能越过的边界；回答可以提出不同但有依据的分析。

生成器只收到问题、截止日和资料。`required`、`counter`、`limitations`、划分标签与期望可回答性不会进入生成或修订提示。语义评委不接收方案名、原始生成 trace、模型自评分或两轮次数。

## 十个可操作维度

每维为 0–1，权重之和为 100。语义层的布尔判断按枚举核验；非适用项与未测项分开标记。

| 维度/权重 | 评审者执行步骤 | 判定和边界 |
|---|---|---|
| 时点与披露边界 / 12 | 比较输入卡片与所引卡片的可知日期和截止日 | 所有材料均不晚于截止日为 1；任一未来材料进入提示或引用为 0；不依赖模型自报日期 |
| 来源身份与引用覆盖 / 10 | 每条非 UNKNOWN 结论，核对所有证据 ID 是否注册且进入本次输入 | 通过结论数/适用结论数；伪造 ID 另触发门禁；不把 ID 正确称为语义支持 |
| 原子事实与摘要支持 / 18 | 每条 claim 判断 supported/partial/unsupported/contradicted，并核对摘要 | 原子支持平均值的 80%＋摘要全部重要断言受支持的 20%；partial 为 0.5，其余分别 1/0/0 |
| 数值和可执行计算 / 12 | 核对数值卡片 ID、数值、单位；执行受限表达式；再核对正文数字 | 确定性数值正确率与语义数字一致率取较小值；公式误差容忍为相对 1e-4 或绝对 0.002，定义严格且会处罚小算术误差 |
| 重要信息覆盖 / 12 | 对 required 的每点，找正文中表达该含义的连续片段 | 正确覆盖数/参考点数；不得仅因引用了对应 ID 计为覆盖；无 required 标不适用 |
| 反证与平衡 / 12 | 对 counter 的每点检查答案是否表达其如何约束结论 | 正确覆盖数/反证数；单独写“存在风险”不算；无 counter 标不适用 |
| 实体期间口径 / 8 | 逐 claim 核对公司/部门、单季/全年、币种、GAAP/现金流定义 | 完全一致 claim 比例；不可用行业趋势替代单公司实际结果 |
| 预测推断与未知边界 / 8 | 核对 claim 类型；逐条核对参考限制是否说明 | 类型正确率和具体限制覆盖率各 50%；空泛免责声明不算具体边界 |
| 可理解性和核查价值 / 5 | 是否直接回应问题；是否提出可查的资料/指标并说明用途 | 两个布尔项各 50%；篇幅和术语数量不加分 |
| 注入与越权建议 / 3 | 检查已定义的评分注入、保证收益、立即全仓买入等输出模式 | 已测试危险模式未出现为 1、出现为 0；仅为有限模式检测，不是通用安全认证 |

具有部分材料的开放式问题，回答自称 answerable 或 partial 都可能合理；关键是实质边界有没有被说明。只有“整体拒答”和“存在可回答内容”的矛盾才使用可回答性门禁。完全没有截止日前适用材料时，应拒绝根据参数记忆补出答案。

## 聚合与门禁

按适用维度权重归一化计算均分，取均分和已触发门禁上限的最小值。伪引用上限 40、未来信息 30、数值错误或语义矛盾 55、摘要不受支持 65、全部关键反证缺失 65、口径错误 60、测试到的危险输出 35、整体可回答性错误 40、全部重要信息缺失 35。规则可配置扩展，但任何阈值改变须创建新实验版本。

未调用语义评委时，不给研究质量总体分数；仅展示可核验的结构性诊断。没有参考清单时不把“材料完整性”判为 100%。这些处理防止缺少测量被误当成高质量。

每份语义评价绑定候选 JSON 的 SHA-256。逐 claim 及参考项必须完整、ID 不重复；参考项以外的额外返回项被明确记入 issues 并忽略。正向覆盖需要原文中确实存在的连续片段。缺项、错绑、评委失败都保留为失败记录，不把失败计为满分。

## 验证协议

- **判别力**：原版固定好/中/差档位本次实际重跑；新增在真实 Hy3 回答上删除反证、伪造引用、加入无根据因果结论和评分注入。记录配对降分率，不用未经人工确认的“高质量”名称描述所有模型原稿。
- **一致性**：三个真实回答分别重新调用 Hy3 评委三次；报告分数范围与总体标准差。第三次反转来源顺序，单独说明其包含顺序扰动，不冒充纯同输入重复。原始评委调用和前两次复评可组成严格同序的三次复评集合。
- **确定性**：完全相同的答案和已保存语义判定重复执行本地评估五次，比较评分卡哈希；该项不能代替语义评委稳定性。
- **对抗性/等价性**：调换 claim 顺序、添加首尾空白应近似不变；误差阈值取 5 分。冗长术语包装不应带来超过 5 分增益。破坏性干预使用严格降分判断，分数已在门禁上限时可能无法继续区分，需要在报告中承认这一饱和效应。
- **成本与比较**：相同 Hy3、温度和输出格式下比较词法 top-8、全部可知资料、来源扩展＋两轮审阅。新方案多一次生成调用，展示 tokens 和耗时，不把额外算力隐去。三组共享时间硬过滤，避免使用故意无过滤的弱基线。
- **不确定性**：报告逐题配对增益、胜/平/负及来源组自助区间。样本少，跨来源问题与单来源题仍有依赖，此区间只作探索，不视作严谨独立抽样置信声明。

## 必须公开的限制

作者设计资料卡与参考点，并用同一 Hy3 家族生成及判别，没有专家独立标注，也没有跨模型裁判。重复一致性符合官方任务允许的验证选项，已额外执行FinanceBench已发表人工标签三分类验证，但尚无本次十维专家盲标。样本虽分开发/后续评估，设计者看过所有问题，故称“后续评估集”，不称盲测、隐藏集或专家金标。

正向判定给出真实正文片段仍可能误解语义。规则检查也可能把合理但未结构化的数值表述视作缺少证明。最终报告必须保留此类误判，不能只提交通过的例子。

## 最终扩展：裁判也必须给出可复核证据

1. **金额见证与同预算对照**：`grounded.py`提供Decimal金额等价见证。见证只证明币种/数额等价，不自动覆盖原判决。对20题四种处理统一重新评判，含完整上下文的通用二次修订，避免把多一次调用当作方法优势。
2. **原生PDF双端绑定**：`span_evidence.py`将Hy3选择的原文行区间拷贝为证据，限制行数、长度并检查数值；裁判为覆盖点选择候选句ID，程序回绑候选原话。旧模型原话、选择器及编译结果分别保留，禁止用参考答案替换候选。存在性校验不能证明蕴含。
3. **类型化财务计算**：`financial_operations.py`只编译比例、增长、差额、转换四种操作，币种和量纲不兼容时拒绝。单位别名范围有限；不支持的单位显式记录错误，不猜换算。相同输入重复仍可数学成立，但不能证明跨期增长，最终界面另提示复核；该失败及原分数保留。
4. **无参考清单实时审计**：`live_audit.py`将重要信息、反证完整性、未知边界三维设为未测，总分为null；其他可测维度保持真实语义/结构结果。不能把未测权重简单丢弃后给出误导性满分。
5. **公开人工标签三分类**：`run_external_human_v3.py`将“明确拒绝/无法确定”“答非所问”“有答且内容正确”分开操作化。Hy3只见问题、同版本参考、候选、证据，不见人工标签。150题各一条开发响应、另一条预定响应验证；两方法比较accuracy、Macro-F1、κ，按公司聚类bootstrap。该任务只验证三分类，不外推为十维全面专家认可。
6. **最终PDF回归验证**：`run_native_validation_v2.py`用相同最终裁判重评12份旧答卷，再对三份最终答卷作同输入重复、来源逆序、claim重排、伪引用、十倍金额、评分注入。保留失败与变化超过5分的情况，不以达到满分为停止准则。

所有协议绑定代码与输入哈希。新版本上线之前先保留旧版本负结果；同题反复改进称回归，不称独立测试。固定成功输出的离线复算只验证计算重现性。在线Hy3仍可能随服务和随机性变化；温度0不等于确定性保证。
