# 调研与方案选择

检索和核验日期：2026-09-09至2026-09-10。仅用论文作者/官方仓库及一手披露支持技术判断。仓库版本、许可检测、README 哈希见 `audit/research_repositories.json`。未运行外部框架的榜单，因此不声称本项目击败这些项目或论文。

## 对照工作与实际借鉴

| 工作 | 与本任务相关的能力 | 本项目借鉴与差异 |
|---|---|---|
| [FinRobot 官方仓库](https://github.com/AI4Finance-Foundation/FinRobot)[^1] | 多步骤财务研究、报告生成与数据服务集成 | 借鉴面向具体报告工作流。其数据服务/框架依赖较多，替换成 Hy3 后仍需本任务评估验证；未直接重装整个框架 |
| [FinanceBench 论文](https://arxiv.org/abs/2311.11944)[^2]与[仓库](https://github.com/patronus-ai/financebench) | 有来源证据的金融 QA；公开仓库为部分样本 | 借鉴证据和来源信息。其清晰答案 QA 不覆盖“观点平衡、遗漏反证”的全部开放式问题；未将其公开小样本冒充完整数据集 |
| [FinQA 论文](https://arxiv.org/abs/2109.00122)[^3]与[仓库](https://github.com/czyssrs/FinQA) | 财务数字推理与程序化解答 | 借鉴计算程序验证；本项目无训练且应用核心仍为开放式简报，不改选任务 2 |
| [RAGChecker 论文](https://arxiv.org/abs/2408.08067)[^4]与[官方实现](https://github.com/amazon-science/RAGChecker) | 将输出拆为 claim，分别诊断检索和生成 | 借鉴原子蕴含核验；新增来源日期门禁、数字程序、材料与反面证据覆盖。仅检查引用存在不能证明蕴含 |
| [FinResearchBench](https://arxiv.org/abs/2507.16248)[^5] | 以逻辑树为中间表示评价金融研究成果 | 说明“金融多维评估＋逻辑图”已有先例。本项目不将原证明图单独包装为首创 |
| [FinRpt](https://arxiv.org/abs/2511.07322)[^6] | 研报数据、多个指标与报告生成框架；包含训练方法 | 借鉴把财务报告作为真实任务。本项目采用纯Hy3调用路线，未使用训练模块 |
| [FinResearchBench II](https://arxiv.org/abs/2607.12252)[^7] | 问题级 rubric、一致性和判别性筛选，并含人类/模型比较 | 提醒稳定指标不一定能区分模型。我们报告重复波动、变形区分和人工验证缺口，不宣称已有专家一致性 |
| [CalibratedRubric](https://arxiv.org/abs/2607.29252)[^8] | rubric 可测性、信息量和任务适应性 | 小样本不适合拟合并宣称稳健 IRT。保留逐维、逐case结果与误判；未执行IRT拟合或专家校准 |
| [MT-Bench / LLM-as-a-Judge](https://arxiv.org/abs/2306.05685)[^9] | 分析顺序、篇幅与自偏好等裁判偏差 | 加入重排、空白、冗长包装、重复和资料顺序变化；同 Hy3 生成/评判偏差仍明确列为限制 |

论文概念作为设计依据，不把论文中的数据集分数或协议结果写成我们的实验结果。后续核对[作者Hugging Face数据页](https://huggingface.co/datasets/PatronusAI/financebench)标明CC-BY-NC-4.0。实验从固定提交下载公开数据与历史响应，仅保存到排除目录供研究；提交包提供下载/校验脚本、记录ID与本项目判定，不再分发原数据或历史回答，也不将其重新许可为Apache。

## 比较候选路线

| 路线 | 可解决问题 | 成本/风险 | 决定 |
|---|---|---|---|
| 继续原 ChronoFin，只扩大模板和报告 | 强化时间、引用和算术核查 | 容易继续堆积合成高分；开放式写作与片面分析弱项仍在 | 保留其底座与历史回归，不作为唯一新增工作 |
| 整体迁移 FinRobot 风格多步骤研究代理 | 较完整研究体验，可接行情和估值 | 外部数据服务密钥、数据许可、报告生成稳定性和交易边界扩大；未必给评估创新增加证据 | 未采用整体迁移方案 |
| 单轮完整资料 Hy3 | 小资料包中很强，结构简单、成本较低 | 长文规模问题仍在，但不应低估其竞争力 | 实际实现为 full_context 强基线 |
| 来源扩展＋反证审阅＋本地计算反馈 | 保留模型中文综合，兼顾支持与限制；算术不依赖模型心算 | 多一次调用；语义裁判仍可能误判；小资料包不代表整本 PDF 检索性能 | 选为 CounterBrief 新增流程，并与基线实测 |

## 技术贡献与比较依据

1. **保留模型原稿与修订稿**：不以摘录替换原稿掩盖错误。改稿必须由 Hy3 基于同一资料、公开规则和执行计算结果完成。
2. **评估材料遗漏与重要反证**：必备信息点不是唯一标准答案；不同文字只要表达同一核心内容可通过。反证覆盖按正文语义判定，不按风险词数量或引用 ID 数量计分。
3. **核查评委的依据**：评委宣称覆盖某点时必须提供候选正文连续片段；本地检查片段确实存在。此检查只能验证引文存在，语义是否相符仍需要模型/人工判断。
4. **让评估器接受同样的审计**：区分破坏性变形、语义等价变形、篇幅包装，报告误报与漏报。冻结代码和样本，把每个分数绑定至答案字节。

比较同时考察后续题表现、误判来源、等价表达波动和调用成本。最终报告公布强基线表现、配对区间及不利结果；方法贡献限定为针对金融证据核查的工程组合与实证验证。

## 调研落实后的实际验证

已完成同调用次数通用修订对照、初稿消融、48次裁判顺序实验、FinanceBench公开人工标签开发/新响应验证、五份原生PDF12题与金额/语义压力集。结果及负结果见最终分析报告。没有运行FinRobot等外部完整系统，因此不声称击败其效果。

双端片段绑定把模型选出的原文行区间与候选句ID交给程序精确截取；类型化财务运算限定单位与操作；二者减轻引文伪造和单位错误，但不证明经济含义。v5同题回归仍有跨期输入重复与引用不完整，作为公开反例。这些是工程与验证贡献，不将多维rubric、claim拆解或反证本身说成新发明。
